# v1.5.0 — 2/3 字词全面补全 + 五笔词优先混排（异响 nakt）

发布日期：2026-10-29

## 症状

- 五笔打「异响」应输入 `nakt`，实际出「那」；
- 不少**二字词/三字词**用五笔打时，出来的是拼音候选（如 `tade`、`guge`、`aiyi`）；
- 反过来，一些五笔词条（东京、薄弱、有没有…）被拼音分栏隐藏，打码出不来回。

根因有两条：

1. 基础 `wubi86` 词库缺大量二字/三字常用词（`nakt` 没有任何词条）；
2. 过滤器的「五笔/拼音分栏」是**二选一**：一个编码既是拼音又对应五笔词时，只能显示一边，
   于是 2/3 字词经常被拼音侧顶掉。

## 修复

### 1. 扩展词库 v2（Release 附件）

`wubi86.extended.dict.yaml` 扩充到约 **147,000** 条（3.2 MB），重点补齐：

- 二字词、三字词（来自中文词频表 + 词典词表），例如 `异响`（nakt）、`扫码`（rvdc）、`高铁`（ymqr）；
- 保留手写词条：杨满钊 / 骑行 / 车店；
- 权重：空码给低权重、弱码提升、强码只在不抢原排序的前提下补充（尽量不改变既有手感）。

### 2. 过滤器「混排模式」

当输入既能切成拼音、又正好是五笔词码时，不再二选一：

```
tade  -> 长有（五笔词） / 他的 / 她的 …（拼音）
guge  -> 平静（五笔词） / 谷歌 / 骨骼 …（拼音）
aiyi  -> 东京（五笔词） / 爱意 / 爱 …（拼音）
```

五笔词永远排在前面，拼音候选跟在后面，两者都不丢。单字冲突仍由
`lua/wubi_override.txt` 处理（例如 `yaa` 只出「试」）。

### 3. 关闭五笔补全候选（推荐配置）

大词库下，`enable_completion` 会为短码生成成百上千条补全，把真正想要的候选/拼音
挤出前几页。推荐在 `wubi_pinyin.custom.yaml` 里加：

```yaml
patch:
  translator/enable_completion: false
```

词表本身已经覆盖常见整词，正常打完整码即可；菜单也更干净。

### 4. 其他

- 过滤器头部候选上限 30 → 200，避免大词库把拼音候选挤出判定范围；
- `lua/wubi_override.txt` 维持 1,122 条不变；
- 释义词表 `cache.txt` 无变化。

## 验证

- `nakt` → 异响（带英文注释）；
- `aiyi` → 东京 / 欧洲旅游 / 莫测高深 / 爱意 …（五笔词在前，拼音在后）；
- `tade` → 长有 / 他的 / 她的 …；`guge` → 平静 / 谷歌 …；`aixu` → 薄弱 / 埃叙 …；
- `shi` → 是 / 时 / 事 …（拼音正常，补全不再淹没）；
- `yaa` → 试；`wq` → 你；`cdtf` → 骑行；`lgyh` → 车店；`rvdc` → 扫码 / 挚友；
- 全拼-only 配置继续生效：`nh` 不出「你好」，`nihao` 正常。

## 升级

1. 替换 `lua/input_text.lua`；
2. 下载 Release 附件 `wubi86.extended.dict.yaml`（3.2 MB）放到 Rime 用户目录；
3. 在方案补丁里加 `translator/enable_completion: false`（推荐）；
4. 重新部署 Rime。

## 已知限制

- 混排仍按词频/权重排序；拼音候选会排在五笔词之后（页数可能靠后）。
- 词库覆盖“词典里有的词”，任意新造组合可以用 `data/wubi_words_extra.txt` 加。
