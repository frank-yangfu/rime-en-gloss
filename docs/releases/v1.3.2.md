# v1.3.2 — 五笔码不再被当成拼音（yaa → 试）

发布日期：2026-10-23

## 症状

五笔要打「试」应输入 `yaa`，候选却是「鸭啊 / 呀 / 丫 / 压 / 亚 / 牙」，整页都找不到「试」。
同类：`eee` 本该出「月」却出「饿饿饿」；`aqi` 出「阿奇」而没有「区」；`nudu` 没有「买」；
`wage` 出「挖个」而没有「代表」；`yaci` 出「牙齿」而没有「度」。

## 根因

1.3.0 的「五笔/拼音分栏」用「能不能完整切成拼音音节」判断输入模式。但**很多合法五笔码
同样能切成音节**：`yaa` = `ya`+`a`、`eee` = `e`+`e`+`e`、`nudu` = `nu`+`du`。
于是这些码被判成拼音，五笔候选被整体过滤掉。

对 `wubi86` 词表 99,082 个码做离线对账：1,793 个码能切成拼音音节，其中 1,122 个属于
「用户真正想要五笔」的情况。

## 修复

1. 新增 `lua/wubi_override.txt`：运行时白名单，一行一个码；命中后**在拼音切分之前**强制
   走五笔模式。文件找不到时静默回退旧行为，不会打不出字。
2. 新增 `tools/gen_wubi_override.py`：离线生成白名单。入表条件：
   - 码能完整切成拼音音节（否则本来就走五笔）；
   - 码本身不是拼音音节（`shi/ni/wo/de` 保留拼音）；
   - 码不在精选拼音词表（`gege`=哥哥、`tade`=他的、`guge`=谷歌 保留拼音）；
   - 拼音词典中同拼写的最大权重 < 1000（`tayi`=他以 这类保留拼音）。
   生成器重跑幂等，并把 `pinyin_keep.txt` 与统计报告一并写出。
3. 纯五笔/纯拼音方案的安全修复：当选中的模式一个候选都没有时，尾段不再按模式过滤，
   避免菜单被截断到前 30 条。

## 验证

- 1,122 个白名单码逐个输入：字符集内可用的 **810 个码 100% 首项命中**对应五笔字；
  312 个码属于 CJK 扩展区生僻字（`extended_charset=常用` 下无候选，开「增广」即可）。
- 200 个未入白名单的碰撞码：候选与修复前完全一致（拼音输入不受影响）。
- 释义注释正常（`yaa, to try; test`、`wq, you` 等）；性能无退化（单键中位 3.75 ms）。
- 删除白名单后整体回退旧行为，无报错。

关键反例：

```
修复前  yaa → 鸭啊  呀  丫  压  亚  牙
修复后  yaa → 试  試  谋划  诫  誡  遮荫

修复前  eee → 饿饿饿  呃呃呃  鹅鹅鹅 …
修复后  eee → 月  朦朦胧胧  胳膊肘 …
```

## 升级

```bash
cp lua/input_text.lua     <Rime 用户目录>/lua/
cp lua/wubi_override.txt  <Rime 用户目录>/lua/
```

重启输入法服务即可（lua 改动无需重新部署）。Windows 一键安装脚本已更新。
释义词表无变化，继续使用 v1.0.0 的 `cache.txt`（MD5 `1871ce8af979af408106a5119feb8c0a`）。

## 备注

- 白名单文件随仓库分发（1,122 条），换过五笔/拼音词典后按 README 重新生成。
- 真正的拼音词（哥哥/他的/谷歌/他以…）仍走拼音，这是刻意保留的。
- 已知限制：312 个生僻码受字符集过滤，需开「增广」。
