# v1.1.0 — 人名组句修复（候选区间保留）

发布日期：2026-10-10

## 修复：打人名只上屏第一个字

**症状**：拼音连打 `lilinfei`（李林菲）、五笔连打 `sniagwqjh`（杨满钊）时，
选第一个字后剩余编码被吞掉，屏幕上只出现第一个字。

**根因**：候选过滤器在给候选加英文注释时，用
`Candidate("table", 0, #code, ...)` 重建了每条候选，把输入区间写死为
「从 0 到整句编码长度」。多段组句（拼音分段、五笔连打、五笔组句）的候选
原本各只覆盖自己那一段，被改写后选择任何一条都会提交整个编码。

**修复**：改用 `ShadowCandidate` 包裹原候选——只替换注释，
start/end 输入区间原样继承；`ShadowCandidate` 不可用时保持原候选不变
（缺英文注释好过组句被破坏）。

**验证**：用真实 Lua 运行时（lupa 5.5）+ librime-lua 桩模拟多段组合：
选「李」后编辑器保留 `nfei` 继续组句（旧实现清空全部编码）。
`tools/selftest.py` 新增回归断言。

## 输入体验：Shift 上屏（示例配置）

把 `"ascii_composer/switch_key/Shift_L": commit_code` 写进
`default.custom.yaml` 的 patch（右 Shift 原本就是 `commit_text`，
左 Shift 原本 `inline_ascii`），即可用 Shift 直接上屏原始输入（英文），
不必按回车——连按回车容易把聊天消息直接发送出去。

## 升级

替换 `lua/input_text.lua` 后重启输入法服务即可（lua 改动无需重新部署）。
词表无变化，沿用 v1.0.0 的 `cache.txt`（MD5 `1871ce8af979af408106a5119feb8c0a`）。
